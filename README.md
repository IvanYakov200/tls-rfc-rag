# RAG с проверяемыми цитатами из RFC

Помощник отвечает на русские вопросы по 20 англоязычным спецификациям TLS. Ответ состоит из утверждений. Для каждого возвращаются дословные выдержки, номер RFC, раздел и байтовые координаты. Когда контекст не покрывает существенную часть вопроса, система возвращает `insufficient`. Рабочий режим — `direct`.

**Основной тест (20 вопросов):** 20/20 по содержанию, 19/20 с полной опорой на цитаты. **Все 73 актуальных вопроса:** 70/73 и 68/73 соответственно. В сводку входят вопросы разработки. На первом прогоне после фиксации отдельного набора blind строгий результат составил 19/20, на повторном — 18/20. [Технический отчёт, 2 страницы](docs/report.pdf) · [Метрики по наборам](results/all_direct/report.md) · [Исходное задание](docs/assignment.pdf)

## Проверка за минуту

Клонируйте репозиторий и перейдите в его каталог (для ZIP откройте папку с `rag.py`).

```sh
git clone https://github.com/IvanYakov200/tls-rfc-rag.git
cd tls-rfc-rag
```

Команды проверки используют стандартную библиотеку Python 3.11–3.13. Сеть и модель для них не требуются.

```sh
python3 rag.py verify
python3 rag.py replay blind-07
python3 rag.py replay test-03 --method dense
PYTHONPATH=src python3 -m unittest discover -s tests -v
```

`verify` заново вычисляет покрытие эталонов, сверяет цитаты с текстом RFC, проверяет привязку оценок к ответам финального прогона и собирает таблицы. Семантические оценки для сохранённых ответов уже выставлены. `replay` показывает конкретный ответ, включая ссылки. Для демонстрации смысловой ошибки откройте `python3 rag.py replay dev-02` и сравните перевод «обходит» со словом *obsoletes* в источнике.

## Живой запрос

Нужны uv, curl и сеть. Запускайте команды из корня проекта. Первая подготовка загружает токенизатор и веса E5, индекс строится на CPU и кешируется в `.runtime/`. Доступ к AnyModel предоставляется через `ANYMODEL_API_KEY` либо локальный файл `.anymodel-key`. Для запуска из GitHub укажите собственный ключ.

```sh
uv sync --frozen --python 3.12
.venv/bin/python rag.py setup
.venv/bin/python rag.py index
.venv/bin/python rag.py ask 'По RFC 7465 клиент предложил только наборы RC4. Что обязан сделать сервер?'
```

В обычном запросе три последовательных вызова `cx/gpt-6.1-sol`: составить до трёх английских поисковых запросов, выбрать 5 фрагментов из 40 и сформулировать ответ. Локальный поиск объединяет multilingual E5-small и BM25. Эмбеддер обрабатывает до 256 токенов на фрагмент; для длинных фрагментов BM25 и генератор видят также текст за этой границей. Программа восстанавливает цитаты из исходных байтов по номерам выдержек. Полная задержка в последнем прогоне — 24,5 с по медиане, 44,2 с по P95. В сохранённых трассах `total_s` охватывает весь запрос, `duration_s` успешного ответа — только финальную генерацию. Ошибки API или формата отделены статусом `generation_failed`.

## Как оценить новый прогон

Для всех наборов выполните три команды. Отдельная папка хранит новые ответы и оценки; повторный запуск продолжает работу по сохранённым ID.

```sh
PYTHONPATH=src .venv/bin/python -m tls_rag.all_questions run   --out .runtime/my-run
PYTHONPATH=src .venv/bin/python -m tls_rag.all_questions judge --out .runtime/my-run
PYTHONPATH=src python3 -m tls_rag.all_questions score         --out .runtime/my-run
```

Оценщик `cx/gpt-6.2-sol` получает вопрос, эталон, ответ и цитаты. Для ручной проверки одного набора:

```sh
.venv/bin/python rag.py run --split test > answers.jsonl
python3 rag.py review-template --split test --answers answers.jsonl --review grades.jsonl
# Заполните correct и unsupported для каждой строки grades.jsonl.
python3 rag.py score --split test --answers answers.jsonl --review grades.jsonl
```

Сверьте все запрошенные факты, условия и силу требования с эталоном. `correct` означает полный верный ответ либо верный отказ. В `unsupported` укажите номера утверждений (с единицы), хотя бы одна существенная часть которых не подтверждена собственными цитатами; при полной поддержке укажите `[]`. Сохраните ID и хеш ответа. Строгий зачёт требует одновременно `correct=true` и пустого списка. Живой запуск зависит от версии API и может дать другой ответ.

## Состав проекта

| Путь | Назначение |
|---|---|
| `rag.py`, `src/tls_rag/cli.py`, `__init__.py` | Запуск из репозитория, команды приложения и объявление пакета. |
| `src/tls_rag/corpus.py`, `retrieval.py`, `faceted.py` | Проверка корпуса и разбиение, индекс E5 и BM25, английские запросы и объединение выдач. |
| `pipeline.py`, `generation.py`, `llm_client.py` в `src/tls_rag/` | Оркестрация, отбор контекста и генерация с цитатами, транспорт AnyModel. |
| `evaluation.py`, `run_review.py`, `all_questions.py`, `judge.py` в том же пакете | Recall и проверка сравнений, ручная рубрика и валидация, полный эксперимент, независимые запросы к модели-оценщику. |
| `tests/test_faceted.py`, `tests/test_generation.py` | Бюджет кандидатов, резервный поиск, выбор рабочего промпта, сбои отбора и генерации, повтор и ссылки. |
| `data/manifest.json`, `data/raw/rfc*.txt` | Источник, дата, SHA-256 и исходные тексты каждого из 20 RFC. |
| `data/questions/` | Вопрос, эталон и допустимые наборы интервалов. Dev — 5, test — 20, holdout — 20, challenge — 8, blind — 20. В test-v1 сохранена исходная редакция для сравнения с dense. |
| `results/comparisons.jsonl` | Поответные данные абляций. Поле experiment разделяет исходный test-v1 и последующий выбор метода на 48 вопросах. |
| `results/first_blind.jsonl` | Первый прогон выбранного метода на новых вопросах, ответы и оценки с хешами. |
| `results/all_direct/` | Полный повтор: answers.jsonl — ответы и время; review.jsonl — объяснения оценщика; metrics.json — сводные числа; report.md — интерпретация и воспроизведение. |
| `docs/assignment.pdf`, `docs/report.pdf` | Задание и техническая записка для проверки. |
| `pyproject.toml`, `uv.lock`, `.gitattributes`, `.gitignore` | Версии зависимостей, упаковка, сохранение исходных байтов, исключения Git. |
