# Ответы с доказательствами по истории TLS

На входе — вопрос на русском, на выходе — утверждения с дословными английскими цитатами, номерами RFC, разделами и исходными байтовыми интервалами. Техническая записка, таблица экспериментов и разбор ошибок находятся в [REPORT.pdf](REPORT.pdf).

## Посмотреть результат без сети и ключа

Из корня репозитория с Python 3.11–3.13:

```sh
python3 rag.py verify
python3 rag.py replay test-13
python3 rag.py replay holdout-09
python3 rag.py replay test-20
```

Первый пример сопоставляет две редакции, второй демонстрирует ошибку выбора операции при совпадении числового предела, третий — отказ. Команда verify проверяет SHA-256 корпуса и соответствие всех сохранённых ссылок исходным байтам, пересчитывает Recall@5 и агрегирует смысловые оценки ИИ-ассистента из results/review.jsonl. Воспроизведение сохранённых ответов детерминировано.

## Задать свой вопрос

Распакуйте весь ZIP, перейдите в каталог `skoltech-rag` и выполните команды ниже. Ключ AnyModel для проверки уже находится рядом с `rag.py` в скрытом файле `.anymodel-key`. Для живого запуска нужны uv, Python 3.12, curl и сеть. Первоначальная загрузка весов E5 выполняется с Hugging Face. Остальная работа с индексом локальна. Для API используются вопрос и выбранные фрагменты публичного корпуса.

```sh
uv sync --frozen --python 3.12
uv run --frozen python rag.py setup
uv run --frozen python rag.py index
uv run --frozen python rag.py ask 'Как в RFC 7525 и RFC 9325 изменились требования к размеру серверного RSA-ключа?'
```

Для запуска с предоставленным ключом переменная окружения не нужна. Если задана `ANYMODEL_API_KEY`, приложение использует её значение. Этот архив предназначен для личной передачи наставнику: живые запросы расходуют лимит владельца ключа. GPU и Ollama для основного режима не требуются. Живой ответ зависит от доступности и версии модели у провайдера.

## Сравнить конфигурации

```sh
uv run --frozen python rag.py run --split test --method dense > dense.jsonl
uv run --frozen python rag.py run --split test --method final > final.jsonl
uv run --frozen python rag.py run --split holdout --method final > holdout.jsonl
python3 -m unittest discover -q
```

dense — multilingual-e5-small и косинусный поиск. hybrid добавляет BM25 и Reciprocal Rank Fusion. scoped при упоминании двух или более известных RFC чередует результаты поиска внутри этих документов. reranked берёт до 40 кандидатов, просит GPT выбрать 5 взаимодополняющих фрагментов и генерирует ответ с одной цитатой на утверждение. final (по умолчанию) применяет тот же поиск и разрешает несколько цитат. Схема ограничивает идентификаторы переданными выдержками. Пустой список утверждений даёт insufficient. Ошибка вызова или схемы считается техническим сбоем. Каждый вызов run выполняет новую генерацию, перенаправьте вывод в новый файл.

## Корпус и результаты

В data/raw лежат 20 полных текстов RFC. В data/manifest.json зафиксированы источник, дата и контрольная сумма. Разбиение учитывает разделы, страницы и абзацы. При сравнении требований учитываются конкретные редакции RFC. Даты публикации не используются как универсальное правило выбора версии.

data/test.jsonl содержит 20 проверочных вопросов, data/holdout.jsonl — ещё 20, подготовленных до второго прогона; data/dev.jsonl — 5 примеров разработки. Для отвечаемых вопросов заданы эталон и допустимые наборы интервалов. Координаты полуоткрытые: original_bytes[start_byte:end_byte].decode("utf-8").

results/final.jsonl хранит пулы, пятёрки и ответы основной конфигурации. results/ablations.jsonl содержит исходные ответы, цитаты и баллы трёх промежуточных GPT-конфигураций. results/retrieval.jsonl хранит пятёрки трёх поисковых контролей. В results/review.jsonl correct означает полностью правильный ответ либо корректный отказ, unsupported содержит номера недостаточно подтверждённых утверждений (с единицы). Строгий зачёт требует correct и пустой unsupported. Отсутствие доказательств для конкретного утверждения отличается от пропущенной части вопроса. Интерпретация метрик и ограничения приведены в отчёте.

## Файлы комплекта

| Файл | Назначение |
|---|---|
| `README.md` | Инструкция по запуску, просмотру сохранённых ответов и сравнению методов. |
| `REPORT.pdf` | Двухстраничная записка с архитектурой, метриками, абляциями и разбором ошибок. |
| `rag.py` | Командная строка: подготовка индекса, запросы, пакетный прогон и просмотр результатов. |
| `pipeline.py` | Собирает поток обработки вопроса: поиск по документам, отбор кандидатов и генерация. |
| `corpus.py` | Проверяет контрольные суммы RFC, разбивает тексты на фрагменты и сохраняет координаты для цитирования. |
| `retrieval.py` | Загружает E5, строит плотный индекс и объединяет его выдачу с BM25. |
| `generator.py` | Вызывает AnyModel, выбирает выдержки и восстанавливает точные цитаты по номерам, указанным моделью. |
| `evaluation.py` | Пересчитывает покрытие доказательств, сверяет цитаты с оригиналами и агрегирует оценки. |
| `test_generator.py` | Проверяет обработку ссылок, пустых ответов, ошибок вызова и обрыва генерации. |
| `pyproject.toml` | Задаёт поддерживаемые версии Python и зависимости проекта. |
| `uv.lock` | Фиксирует версии пакетов для воспроизводимой установки. |
| `.gitattributes` | Сохраняет байты исходных RFC при работе с Git и фиксирует переносы строк для кода и JSON. |
| `.gitignore` | Исключает из Git ключ, архив для передачи, окружение Python и кеши. |
| `.anymodel-key` | Ключ доступа к AnyModel для живого запуска. |
| `data/manifest.json` | Реестр источников с датами публикации, URL, размерами и SHA-256. |
| `data/dev.jsonl` | Пять примеров для разработки. |
| `data/test.jsonl` | Основные 20 проверочных вопросов с эталонами и координатами доказательств. |
| `data/holdout.jsonl` | Вторые 20 вопросов для проверки выбранной конфигурации. |
| `results/final.jsonl` | Сохранённые ответы основной конфигурации на 40 вопросов, кандидаты, выбранные фрагменты и цитаты. |
| `results/retrieval.jsonl` | Первые пять фрагментов каждого поискового контроля для пересчёта Recall@5. |
| `results/ablations.jsonl` | Ответы промежуточных конфигураций на основном тесте для сравнения вклада компонентов. |
| `results/review.jsonl` | Поответная оценка правильности и номера недостаточно подтверждённых утверждений. |
