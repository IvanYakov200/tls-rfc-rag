# Поиск доказательств в истории TLS

Локальная RAG-система отвечает на русские вопросы по 20 англоязычным RFC. Ответ сопровождают цитаты, номер документа и полуоткрытый интервал байтов в неизменённом оригинале. Если данных мало, система может отказаться от ответа. Валидатор проверяет совпадение цитаты с оригиналом. Смысловую связь утверждения с цитатой оценивают отдельно.

## Быстрая проверка для ревьюера

Требуется Python 3.11–3.13. Команды выполняются из корня проекта. Для просмотра сохранённых прогонов доступ к сети и модели не нужны.

```sh
python3 rag.py verify
python3 rag.py metrics --split dev
python3 rag.py replay --split dev --id dev-04 --method A
```

Исходники RFC находятся в `data/raw/`. В `data/manifest.json` указаны даты, URL и SHA-256. В `data/dev.jsonl` лежат 5 пробных вопросов, в `data/test.jsonl` — 20 отдельных вопросов, эталонные ответы и допустимые наборы доказательств. Для числовых полей `start_byte` и `end_byte` достаточно прочитать `original_bytes[start_byte:end_byte].decode("utf-8")`. Результаты каждого вопроса содержат упорядоченные идентификаторы пяти поданных фрагментов, исходный JSON модели и результат проверки ссылок.

## Интерактивная проверка в Jupyter

Из корня проекта выполните `sh scripts/review`. Для старта нужен uv. Откроется локальный JupyterLab с ноутбуком `rag_review.ipynb`. Выполните **Run → Run All Cells** для просмотра сохранённого примера. В разделе **Свой вопрос** включите `run_live = True`, измените вопрос и выполните ячейку сочетанием **Shift + Enter**. Следующая ячейка покажет полный контекст каждого метода. Для живых запросов подготовьте модели и окружение по инструкции ниже. Ноутбук автоматически использует порт 11439 при наличии локального каталога моделей проекта, а явно заданный `OLLAMA_HOST` имеет приоритет.

## Повторный эксперимент

Проверенная среда разработки — Apple Silicon, macOS 14.6.1, 8 ГБ, Python 3.12.12, Ollama 0.11.7. Установите uv и Ollama для своей ОС. Первый запуск скачает веса. Оригиналы RFC включены в репозиторий. Предусмотрите около 5 ГБ свободного места под окружение, кеш и модели.

```sh
uv sync --frozen --python 3.12.12
uv run --frozen python rag.py setup
uv run --frozen python rag.py index
```

В отдельном терминале запустите `ollama serve`, если приложение Ollama ещё не запустило сервер. Затем выполните следующие команды.

```sh
ollama pull qwen3:4b-instruct-2507-q4_K_M
uv run --frozen python rag.py ask 'Какие хеши запрещены в signature_algorithms по RFC 9155?' --method B
uv run --frozen python rag.py run --split dev --methods A B C
uv run --frozen python rag.py run --split test --methods A B C
python3 rag.py verify
python3 rag.py metrics --split test
```

Адрес Ollama по умолчанию — `http://127.0.0.1:11434`. Переменная `OLLAMA_HOST` позволяет задать другой локальный порт. После загрузки обеих моделей генерация и поиск работают локально. Для повторной индексации используется версия E5 с зафиксированной ревизией и SHA-256 обоих файлов. Lock-файл фиксирует зависимости Python. Версии драйверов и реализация матричных операций могут влиять на генерацию. Сохранённые трассы позволяют сверять конкретный вывод.

## Что сравнивается

A использует `multilingual-e5-small`: исходный русский вопрос с префиксом `query:`, английский текст с `passage:`, mean pooling с маской, L2-нормализация и полный косинусный поиск. Для 2 833 фрагментов достаточно матрицы NumPy. B добавляет BM25 по тому же запросу с RRF (по 40 кандидатов, константа 60). C заменяет только запрос BM25 на английский перевод того же вопроса из локальной Qwen. Во всех вариантах совпадают разбиение на фрагменты, top-5, генератор и инструкция для ответа.

**Дополнительный эксперимент D.** При ручной проверке вопроса про RC4 метод B нашёл общий запрет выбора RC4. Условие «если предложен только RC4» находилось на следующей странице того же раздела RFC 7465. Метод D берёт ранжирование B и вслед за найденным фрагментом включает продолжение с соседней страницы, если номер RFC и раздел совпадают. В контекст по-прежнему попадает пять фрагментов. Продолжение может вытеснить другой источник. Вариант D появился после разбора вопроса, близкого к `test-01`, поэтому успех на этом примере учитывается как регрессионная проверка. Основное сравнение A/B/C проводится отдельно.

```sh
uv run --frozen python rag.py ask 'По RFC 7465 клиент предлагает только наборы RC4. Что обязан сделать сервер?' --method D
```

`corpus.py` отвечает за парсинг и координаты источников, `retrieval.py` — за оба вида поиска, `local_llm.py` — за вызов Ollama и проверку точных цитат, `rag.py` — за запуск и оценку. `insufficient` означает отказ модели, `invalid_evidence` — отклонённый ответ с нарушением формата или привязки цитаты, `answered` — ответ с восстановленными цитатами. Сохранённый исходный вывод помогает различить эти случаи.

Evidence Recall@5 — доля размеченных фрагментов доказательства, покрытых пятью результатами. Для вопроса с альтернативными наборами берётся максимальное покрытие, затем среднее по отвечаемым вопросам. Метрика `complete` считает вопросы, где найден целый набор. Отказы оцениваются отдельно. Покрытие эталона зависит от полноты разметки альтернатив.

Документация моделей и инструментов доступна на [странице E5](https://huggingface.co/intfloat/multilingual-e5-small), [странице Qwen](https://ollama.com/library/qwen3:4b-instruct-2507-q4_K_M), в [инструкции Ollama](https://docs.ollama.com/) и [инструкции uv](https://docs.astral.sh/uv/).
