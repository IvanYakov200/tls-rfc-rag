# Сравнение на 20 финальных вопросах

Исходные данные — `data/test.jsonl` и 60 сохранённых трасс `results/test-{A,B,C}.jsonl`. Ревизия основного эксперимента — `40b8607`. Одинаковые 16 отвечаемых и 4 неотвечаемых вопроса для каждого метода. Вариант D разработан после наблюдения ошибки с RC4 и оценивается отдельно.

| Показатель | A · dense | B · dense + BM25 | C · B с переводом для BM25 |
|---|---:|---:|---:|
| Evidence Recall@5 по 16 отвечаемым | 37,5% | 60,4% | 59,4% |
| В top-5 найден полный набор доказательств | 5/16 | 7/16 | 7/16 |
| Система выдала содержательный ответ | 4/20 | 8/20 | 7/20 |
| Правильный полный ответ среди отвечаемых | 2/16 | 4/16 | 3/16 |
| Верный отказ на неотвечаемый вопрос | 4/4 | 4/4 | 4/4 |
| Сквозная accuracy с учётом верных отказов | 6/20 | 8/20 | 7/20 |
| Сквозная accuracy при проверке также всех цитат | 6/20 | 6/20 | 5/20 |
| Ответ отклонён из-за формата или некорректной ссылки | 8/20 | 7/20 | 9/20 |

Recall пересчитан по интервалам в оригинальных файлах. Для каждого отвечаемого вопроса считаем долю эталонных фрагментов, полностью покрытых первыми пятью результатами. При наличии нескольких допустимых наборов берём максимальную долю, затем усредняем по вопросам. Эквивалентная формулировка в другом месте RFC может дать содержательную поддержку при низком измеренном recall.

Оценку содержания выполнил ИИ-ассистент по каждому сохранённому ответу и эталону. Балл за отвечаемый вопрос требует правильных и понятных по-русски ответов на все его существенные части. Повторы допустимы. Ложное утверждение, искажение нормативного уровня или непонятный перевод обязательного действия приводят к нулю. В строгом варианте каждое существенное утверждение, включая дополнительные факты, также должно подтверждаться собственной цитатой с учётом запрошенной редакции. У неотвечаемого вопроса засчитывается только явный отказ `insufficient`. Рубрика применена после прогона. Для итогового отчёта желательна независимая вычитка оценок человеком.

## Какие ответы засчитаны

| Метод | Номера правильных содержательных ответов | Из них с полной опорой на собственные цитаты |
|---|---|---|
| A | 04, 07 | 04, 07 |
| B | 02, 04, 08, 09 | 02, 08 |
| C | 02, 04, 08 | 08 |

Во всех трёх методах дополнительно засчитаны отказы на 17–20. Для 11–16 требовалось объединить сведения из нескольких источников. Ни один метод не дал полного правильного ответа на эти шесть вопросов.

## Решения, влияющие на оценку

- **B, 01.** Цитата верная. Перевод «сервер обязан завершить ручку» не сообщает русскоязычному пользователю, что сервер должен прервать рукопожатие. Если считать английскую цитату частью ответа, этот случай можно зачесть и получить 9/20 вместо 8/20.
- **B/C, 04.** Основной ответ о применимости encrypt-then-MAC верен. Цитата при дополнительном утверждении не подтверждает все приведённые детали, в частности примеры алгоритмов. **B, 09.** Верно названы пороги и изменение требований, но в цитате слово MUST относится к DH, а для ECDH приведены только размеры. **C, 02.** Число 0x0101 равно 257, но предъявлена цитата из RFC 8446 при явно заданном RFC 7919.
- **B, 11.** Для renegotiation_info ответ 0x0013 вместо 0xff01. В приложенной цитате вообще нет числа. Это реальный пример категоричной ошибки с технически валидной ссылкой.
- **C, 01.** Модель пишет, что сервер должен послать alert, хотя её собственная цитата говорит MAY. Поиск нашёл весь эталон.
- **B, 03, 05, 07.** В пяти фрагментах есть полный размеченный набор. Все три сырых ответа оказались незавершённым JSON. В B всего пять непарсируемых JSON среди семи отклонённых ответов, ещё два содержат ссылку с номером 0. В трассах отсутствует причина остановки генерации, поэтому влияние лимита вывода требует отдельного замера.

## Дополнительная проверка поиска по явно названным документам

Если вопрос явно называет минимум два RFC из корпуса, исходный запрос ищется отдельно в каждом из этих документов. В итоговые пять мест по очереди берётся очередной результат каждого документа. Для остальных вопросов используется B. Глобальные статистики BM25, эмбеддинги и бюджет контекста те же. Эксперимент проведён после просмотра ошибок на этом наборе.

Для воспроизведения выполните `.venv/bin/python -m scripts.compare_scoped` из корня проекта. Скрипт сначала сверяет все исходные выдачи B с основным прогоном. Результаты находятся в `results/scoped-retrieval.jsonl`.

| Выборка | Recall@5 B → поиск по документам | Весь комплект доказательств |
|---|---:|---:|
| Все 16 отвечаемых вопросов | 60,4% → 66,7% | 7/16 → 9/16 |
| 6 вопросов на несколько источников | 27,8% → 44,4% | 0/6 → 2/6 |

Полное покрытие появилось у вопросов 13 и 14. На остальных вопросах измеренный recall сохранился. Для независимой оценки нужны новые вопросы с разметкой, подготовленной до просмотра выдачи.

В отдельном прогоне той же Qwen на этих двух вопросах 13 снова завершился незакрытым JSON. На вопросе 14 исходный B отказался, а с новым контекстом модель правильно указала обязательное прекращение рукопожатия, необязательный alert для RC4 и обязательный illegal_parameter для CertificateVerify с SHA-1. Цитаты проверены по оригиналам. Трассы находятся в `results/scoped-answers.jsonl`. Сквозная accuracy по всем 20 для этого варианта не измерялась.
